### Порівняння режимів публікації
| RID | Режим | Розмір publish | Потрібен runtime |
| :--- | :--- | :--- | :--- |
| win-x64 | Self-contained | 72 МБ | Ні |
| win-x64 | Framework-dependent | 0.185 МБ| Так (.NET 10) |

- **Self-contained**: пакує застосунок разом із віртуальною машиною .NET Runtime та базовими бібліотеками. Застосунок повністю автономний, але займає багато місця на диску.
- **Framework-dependent**: містить лише скомпільований код застосунку та зовнішні залежності. Має компактний розмір, але потребує відповідної версії .NET Runtime на машині користувача.


## Лабораторна робота 3: Імпорт даних

### Формат файлу даних (`data/sample.csv`)
- **Кодування:** UTF-8
- **Роздільник колонок:** `;` (крапка з комою)
- **Заголовок:** присутній у першому рядку (`id;sku;name;unit;quantity`), ігнорується парсером
- **Коментарі:** рядки, що починаються з символу `#`, ігноруються

#### Структура колонок:
1. `Id` — текстовий ідентифікатор товару (наприклад, `P-001`)
2. `Sku` — артикул товару (обов'язкове поле)
3. `Name` — назва товару (обов'язкове поле)
4. `Unit` — одиниця вимірювання (`шт`, `кг`, `м` тощо)
5. `Quantity` — кількість, ціле невід'ємне число (`>= 0`)


## Лабораторна робота 4: Інваріанти

   - Метод: `Create`
   - Виняток: `ArgumentException`
2. **Кількість товару не може бути від'ємною при створенні.** 
   - Метод: `Create`
   - Виняток: `ArgumentOutOfRangeException`
3. **Неможливо видати більше товару, ніж є на залишку.** 
   - Метод: `Issue`
   - Виняток: `InvalidOperationException`

# Система управління складом (CrossApp) | Лабораторна робота №6

Консольний застосунок на C# .NET, який демонструє принципи багаторівневої архітектури, ізоляції доменної моделі та патерн Repository.

## Мета проєкту
Побудова надійного фундаменту програми, де бізнес-логіка повністю відділена від інтерфейсу користувача (консолі), а дані можуть зберігатися у різних джерелах без зміни основного коду.

## Основні компоненти
* **Доменна модель (`Product`):** Базова сутність, яка описує товар (Артикул, Назва, Одиниця виміру, Залишок).
* **Сховища даних (Stores):** 
  * `InMemoryCatalogStore` — зберігає дані в оперативній пам'яті під час роботи програми.
  * `FileCatalogStore` — зберігає та читає дані з текстового файлу.
* **Розділення відповідальності:** Весь функціонал роботи з даними винесено в бібліотеку `Core`, а взаємодія з користувачем — у проєкт `Cli`.

## Структура проєкту
* **`src/Core/Domain/`** — Сутності (`Product`) та інтерфейси сховищ.
* **`src/Core/Stores/`** — Реалізація сховищ (`InMemoryCatalogStore`, `FileCatalogStore`).
* **`src/Core/SampleData.cs`** — Генерація базового набору товарів.
* **`src/Cli/Program.cs`** — Точка входу, клієнтська частина застосунку.

## Запуск
Перейдіть у корінь проєкту та виконайте команду:
dotnet run --project src/Cli

# Аналітика складу (CrossApp) | Лабораторна робота №7

Розширення складської системи на C# .NET для генерації аналітичних звітів за допомогою технології LINQ to Objects.

## Мета проєкту
Реалізація аналізу списків товарів (фільтрація, сортування, групування) без використання ручних циклів, а також архітектурне відокремлення результатів звітів від доменної моделі.

## Основні компоненти
* **ReportService (LINQ):** Центральний сервіс у ядрі, що містить запити:
  * `Where` — фільтрація дефіцитних товарів.
  * `OrderBy/ThenBy` — стабільне сортування для топ-товарів.
  * `GroupBy` — групування за одиницею виміру.
  * `Sum/Average/Max` — агрегатні обчислення.
* **DTO (Data Transfer Object):** Класи `StockLine` та `GroupSummary`, які слугують безпечними "контейнерами" для передачі відфільтрованих даних у консоль, приховуючи справжню структуру `Product`.
* **Відкладене виконання (Lazy Evaluation):** Запити не виконуються до моменту їхньої матеріалізації (наприклад, виклику `ToList()`), що гарантує обробку найактуальніших даних.

## Структура проєкту
* **`src/Core/Reports/`** — DTO-моделі та сервіс генерації звітів `ReportService.cs`.
* **`src/Cli/Program.cs`** — Оновлений клієнт із меню (`switch`) для обробки різних команд звітів та форматованого виводу на екран.
